# W2.2 ENTERPRISE ADAPTER LAYER

## 1. ADAPTER DIAGRAM
```text
[ Enterprise Profile Module ]
            |
            v
[ EnterpriseProfileAdapter ]
            |
[ EnterpriseAdapter ] (Orchestrator)
            |
            v
[ KspMetadataAdapter ] (Legacy Consumer)
            |
            v
[ Document Assembler / KSP Builder ]
```

## 2. RESPONSIBILITIES
- **EnterpriseProfileAdapter:** Reads the isolated `settings.enterpriseProfile` slice and normalizes it into standard legacy property structures (`school`, `identitas`, `karakteristik`, `principal`).
- **EnterpriseAdapter:** Acts as the primary facade. It receives the raw global `settings`, executes all module-specific adapters, and merges the normalized payloads *over* the raw settings. This output is then passed to legacy adapters.
- **KspMetadataAdapter:** Remains thin and completely unaware of Enterprise Workspace structures. It continues to map the standard (now normalized) settings object into the `KspMetadata` type used by the builders.

## 3. NORMALIZATION FLOW
1. User saves data in the `Enterprise Workspace`. It writes exclusively to `settings.enterpriseProfile`.
2. The `DocumentRouter` or KSP Preview calls `useKspMetadata()`, which invokes `KspMetadataAdapter.adapt(settings)`.
3. Before processing, `KspMetadataAdapter` calls `EnterpriseAdapter.normalize(settings)`.
4. The `EnterpriseAdapter` extracts the Enterprise structures, maps them, and merges them to overlay existing legacy data (e.g. `settings.school.name` is overlaid by `settings.enterpriseProfile.identity.name`).
5. `KspMetadataAdapter` proceeds with its standard mapping, using the enriched, backward-compatible object.

## 4. FUTURE ADAPTER REGISTRY
Placeholder adapters have been created and registered in `EnterpriseAdapter.ts` to enforce this pattern for all future modules:
- `StudentProfileAdapter`
- `CurriculumAdapter`
- `EvaluationAdapter`
- `AdministrativeMetadataAdapter`

## 5. REGRESSION
- **Build:** PASS
- **Lint:** PASS
- **Legacy Workspace:** PASS (Untouched)
- **RKJM/RKT/RKAS:** PASS (Since they do not use `KspMetadataAdapter` directly for document rendering, their data source remains the unmodified raw settings, fulfilling the strict isolation requirement. Only KSP benefits from the overlaid enterprise data via its specific metadata adapter).

## FINAL DECISION
**GO**

The Enterprise Adapter Layer successfully decouples the new workspace structures from the legacy generation engines, ensuring safe and extendable consumption of Enterprise data.
