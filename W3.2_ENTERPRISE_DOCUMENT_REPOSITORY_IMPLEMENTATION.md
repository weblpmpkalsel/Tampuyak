# W3.2 ENTERPRISE DOCUMENT REPOSITORY IMPLEMENTATION

## 1. FILES CREATED
- `src/enterprise/document/library/types/EnterpriseDocumentTypes.ts`: Defines `DocumentStatus`, `DocumentSource`, `ReferencedBy`, and `EnterpriseDocumentProps`.
- `src/enterprise/document/library/models/EnterpriseDocumentModel.ts`: An immutable representation of an Enterprise Document containing logic for cloning updates and tracking references.
- `src/enterprise/document/library/repository/EnterpriseDocumentRepository.ts`: Defines the `IEnterpriseDocumentRepository` interface and implements `InMemoryEnterpriseDocumentRepository`.
- `src/enterprise/document/library/registry/EnterpriseDocumentRegistry.ts`: A singleton registry that binds the repository implementation for global use.
- `src/enterprise/document/library/service/EnterpriseDocumentService.ts`: Business logic layer handling create, updateMetadata, archive, restore, find, list, reference, and dereference operations.

## 2. REPOSITORY DESIGN
The implementation establishes a clean, decoupled layer for document persistence. It currently utilizes an In-Memory Repository, which implements the generic `IEnterpriseDocumentRepository` interface, allowing a future swap to a Cloud-based or local indexedDB storage without modifying the Service layer.

## 3. DOCUMENT MODEL
The `EnterpriseDocumentModel` represents the core Enterprise Asset. It is implemented as an immutable model. Updates are handled via the `cloneWith` method, ensuring strict unidirectional data flow and predictability. Metadata fields natively support dynamic categorization without hardcoding document types (e.g., KSP, SOP, etc.).

## 4. SERVICE CAPABILITIES
The `EnterpriseDocumentService` acts as the orchestrator for all document lifecycle actions, strictly using Document IDs:
- **Create**: Instantiates a new document with `version: 1` and status `Draft`.
- **Reference / Dereference**: Ensures modules (KSP, RKJM, etc.) only reference Document IDs via the `ReferencedBy` collection. Never duplicates files.
- **Archive / Restore**: Implements soft-deletion (status transitioning) to protect referenced assets from permanent data loss.
