# KSP GOLD M3.0: BAB III (Pengorganisasian Pembelajaran)
## Enterprise Implementation Audit

## Executive Summary
This document provides a comprehensive Enterprise Architecture Audit for the implementation of BAB III (Pengorganisasian Pembelajaran) within the KSP GOLD engine. The audit verifies that BAB III can be fully realized while strictly adhering to Indonesian Government regulations, preserving the Canonical Document model, and guaranteeing zero regression.

## 1. Government Structure Audit
Based on current Indonesian educational regulations (e.g., Permendikbudristek No. 12 Tahun 2024 and relevant Kepmendikbudristek guidelines), *Pengorganisasian Pembelajaran* must include the following subsections:

- **Pengaturan Beban Belajar / Pendekatan Pembelajaran** (Mandatory)
- **Intrakurikuler** (Mandatory)
- **Kokurikuler / Projek Penguatan Profil Pelajar Pancasila (P5)** (Mandatory)
- **Ekstrakurikuler** (Mandatory)
- **Program Inklusif / Bimbingan Konseling** (Context-dependent / Optional based on school characteristics)

## 2. Knowledge Domain Audit
Each subsection maps to specific knowledge domains:
- **Pengaturan Beban Belajar**: *Operational Knowledge* (Allocation of effective weeks, learning approach: subject-based, thematic, or block scheduling). Ownership: School Administration.
- **Intrakurikuler**: *Operational Knowledge* (Curriculum structure, mapping of Capaian Pembelajaran / CP). Ownership: Curriculum Deputy / Teachers.
- **Kokurikuler (P5)**: *Strategic & Operational Knowledge* (Selection of national themes, integration strategy). Ownership: School P5 Coordinator.
- **Ekstrakurikuler**: *Operational Knowledge* (Mandatory scout/Pramuka, optional clubs). Ownership: Student Affairs Deputy.

## 3. Knowledge Source Audit
Authoritative sources for BAB III data:
- **Intrakurikuler**: Sourced via Teacher Attachment Gateway (`TAMPUYAK TEACHER`). CP, ATP, and Modul Ajar are too volatile for static generation and must be handled via attachments.
- **Kokurikuler (P5)**: School Metadata (Theme selections) and Teacher Attachment Gateway (Modul Projek).
- **Ekstrakurikuler**: School Metadata (List of programs) and Teacher Attachment Gateway (Syllabus/Jadwal).
- **Pengaturan Beban Belajar**: Regulatory Knowledge (National baseline hours) intersected with School Metadata (Actual calendar mapping).
*(Rule: Never invent AI-generated learning schedules or syllabus data).*

## 4. Builder Strategy
- **Existing Builders Reusable**: `LearningOrganizationBuilder` currently handles basic school level, academic time, and team structures.
- **New/Expanded Builders Required**: 
  - Enhance `LearningOrganizationBuilder` to process learning approaches (Blok vs. Parsial).
  - Create/enhance `CurriculumStructureBuilder` to parse specific intracurricular and extracurricular metadata.
- **Responsibilities**: The builders will validate incoming workspace metadata against Regulatory bounds (e.g., minimum weeks) and return a pure semantic `LearningOrganizationKnowledge` payload.

## 5. Assembler Strategy
- **Payload Composition**: The Assembler (`KspDocumentAssembler.ts`) will orchestrate `LearningOrganizationBuilder` and inject the result into `buildKspBab3Section`.
- **Dependency Boundaries**: The Assembler remains the sole orchestrator. `KspBab3Structure.ts` will strictly consume the parsed knowledge payload, devoid of metadata fetching logic.

## 6. Government Fidelity Audit
- **Rule Adherence**: The structure complies with the mandated separation of Intrakurikuler, Kokurikuler, and Ekstrakurikuler.
- **No AI Paraphrasing**: Static government definitions of P5 or Intrakurikuler will remain isolated. Dynamic school data will be injected strictly as lists, tables, or attachments.
- **Teacher Boundaries**: The utilization of the `ATTACHMENT` block (e.g., `tampuyak://teacher-gateway/intrakurikuler`) correctly delegates volatile administrative documents (RPP, Modul Ajar) to teachers, avoiding bloated or hallucinatory AI text.

## 7. Canonical Mapping Audit
All BAB III requirements can be fulfilled using the existing `CanonicalDocumentTypes.ts`:
- `HEADING` (Levels 1-3)
- `PARAGRAPH`
- `LIST` (For extracurriculars and P5 themes)
- `TABLE` (For curriculum structure summaries and learning space utilization)
- `ATTACHMENT` (Crucial for linking external Modul Ajar and Silabus without breaking document flow).
*Conclusion: No new Canonical Block types are required.*

## 8. Regression Audit
- **Renderer**: Untouched. The ELE and ELPS Lite handle presentation safely.
- **Knowledge**: Untouched, only extended through pure functions.
- **Builders**: Isolated and fully tested.
- **Zero Regression**: Achievable. Existing BAB I and BAB II structures share no coupled logic with BAB III.

## 9. Implementation Sequence Roadmap
To safely implement BAB III, the following sequence is recommended for future sprints:
1. **M3.1**: Extend `LearningOrganizationKnowledge` interfaces to support detailed Curriculum Structures.
2. **M3.2**: Implement *Pengaturan Beban Belajar* & *Pendekatan Pembelajaran* (Tables & Paragraphs).
3. **M3.3**: Implement *Intrakurikuler* (Attachment Gateway & Summary Tables).
4. **M3.4**: Implement *Kokurikuler / P5* (Theme Lists & Integration).
5. **M3.5**: Implement *Ekstrakurikuler* (Mandatory vs. Choice Lists).
