# KSP GOLD M3.3: Academic Calendar Domain Enterprise Audit

## Executive Summary
This document executes the Enterprise Audit for the Academic Calendar Domain (BAB III). It determines the authoritative sources, ownership, and structural mapping for calendar-related data across TAMPUYAK OS. The audit confirms that the Academic Calendar is a distinct **Planning Knowledge** domain that must be centralized to prevent duplication across the enterprise.

## 1. Government Structure Audit
Current Indonesian educational regulations mandate that the Academic Calendar within the KSP must outline:
- **Semester Boundaries** (Awal dan akhir semester)
- **Effective Weeks** (Minggu efektif belajar)
- **Assessment Periods** (Jadwal asesmen sumatif / STS, SAS)
- **Report Distribution** (Pembagian buku laporan pendidikan)
- **National Holidays** (Libur nasional)
- **School Holidays** (Libur jeda semester, libur akhir tahun)
- **Project Weeks** (Jadwal pelaksanaan P5)
- **School Events** (Kegiatan khusus sekolah)

## 2. Knowledge Classification
The Academic Calendar belongs to the **Planning Knowledge** domain. It is an intersection of external regulatory constraints (Government Holidays) and internal operational decisions (School Events, Assessment periods).

## 3. Ownership & Source Matrix

| Calendar Element | Authoritative Source | Owner |
| :--- | :--- | :--- |
| **National Holidays** | National Government Decree (SKB 3 Menteri) | Government |
| **Regional Holidays** | Provincial/District Education Office Kalender Pendidikan | Education Office |
| **Semester Boundaries** | District Education Office Kalender Pendidikan | Education Office |
| **Effective Weeks** | School Planning Module (Derived from Govt bounds) | Curriculum Vice Principal |
| **Assessment Periods** | School Policy / Planning Module | Curriculum Vice Principal |
| **Project Weeks (P5)** | School Policy / Planning Module | P5 Coordinator |
| **Report Distribution** | School Policy / Planning Module | Principal / Curriculum |
| **School Events** | School Workspace Metadata | Principal |

## 4. Lifecycle & Mutation Matrix

| Calendar Element | Lifecycle | Update Frequency |
| :--- | :--- | :--- |
| **National Holidays** | Annual | Yearly (Minor mid-year revisions) |
| **Regional Boundaries** | Annual | Yearly |
| **Assessment Periods** | Semester/Annual | Semesterly |
| **School Events** | Semester/Annual | Monthly/Semesterly |

## 5. Consumer Matrix
The centralized Academic Calendar is consumed across TAMPUYAK OS by:
- **KSP (BAB III):** Renders the static yearly overview for compliance.
- **Teacher Workspace:** Dictates teaching schedules, Modul Ajar pacing, and ATP milestones.
- **Attendance Module:** Determines active school days vs. holidays.
- **Planning Module:** Orchestrates school resource allocation.
- **Dashboard & AI:** Provides temporal context for AI insights and user dashboards.

## 6. Duplication Analysis
**Critical Rule:** The Academic Calendar SHALL exist only once. 
If KSP requires the calendar, it must NOT store its own local copy or allow manual text entry of dates that could drift from the Teacher Workspace. KSP will purely reference or ingest the global `AcademicCalendar` master data object. 

## 7. Builder Strategy
- **Pure Consumer:** The `LearningOrganizationBuilder` (or a dedicated `AcademicCalendarBuilder`) will accept a pre-computed array of calendar events and periods.
- **No Calculations:** The Builder will NOT calculate effective weeks or determine holiday overlaps. All temporal logic is handled upstream by the Planning Module / Service layer.

## 8. Assembler Strategy
- The `KspDocumentAssembler` will fetch the calendar payload from the `EnterpriseMasterDataRegistry` (or `KspMetadataAdapter`) and pass it as an immutable payload to the Builder.

## 9. Canonical Mapping
- **`TABLE`**: Used to present monthly event breakdowns (e.g., Month, Event Date, Description).
- **`LIST`**: Used to summarize recurring events or key dates.
- **`PARAGRAPH`**: Used to state overarching calendar policies.
- **No new Canonical Blocks** are required.

## 10. Future Registry Readiness
The audit confirms the necessity of a dedicated **Academic Calendar Registry** within the Master Data layer. This registry will merge Government Calendars with School Policies, producing a unified timeline consumed by KSP and other enterprise apps.
