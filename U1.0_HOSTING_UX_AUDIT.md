# U1.0 HOSTING UX AUDIT REPORT

## 1. Navigation Audit
**Legacy Menu vs. Enterprise Menu Conflict**
Currently, the application displays a dual-navigation system that heavily confuses the user. There is an outer sidebar containing "Beranda", "Data Sekolah", "Workspace Enterprise", "Dokumen Perencanaan" and others. Clicking "Workspace Enterprise" opens an inner sidebar with its own overlapping categories ("Dashboard", "School Profile", "Curriculum Hub", "Compliance Center"). This is highly disjointed.

**Dead Buttons & Hidden Modules**
- "Kalender Pendidikan" is visible but disabled (opacity-50, cursor-not-allowed).
- Many menus inside the inner `WorkspaceModuleRegistry` are marked with `WIP` badges (e.g., Student Pedagogical Profile, Evaluation Hub, Professional Development, Compliance Center). 
- Inner `Curriculum Hub` has WIP badges despite functioning as the central engine for KSP.
- The `Publish` button under the KSP sidebar is marked `cursor-not-allowed`.

## 2. Terminology Audit
**Developer-Centric Terms (MUST REMOVE)**
- `TAMPUYAK OS` and `School Operating System` (Overly technical for end-users).
- `Workspace Enterprise` / `Enterprise Workspace`
- `Curriculum Hub`
- `Compliance Center`
- `Administrative Metadata`
- `Student Pedagogical Profile`
- `Evaluation Hub`
- `Planning Intelligence`
- `Pusat Audit` / `Audit Explorer`
- `Pusat Pengetahuan` / `Knowledge Graph`

**Recommended Replacements**
- "School Profile" ➔ "Profil Sekolah"
- "Student Pedagogical Profile" ➔ "Karakteristik Peserta Didik"
- "Curriculum Hub" ➔ "Pengorganisasian Pembelajaran"
- "Evaluation Hub" ➔ "Evaluasi Kurikulum"
- "Document Library" / "Pusat Pengetahuan" ➔ "Perpustakaan Dokumen"
- "Administrative Metadata" ➔ "Administrasi Dokumen"

## 3. Usability Problems
- **Inconsistent Language:** Mixing English ("School Profile", "Curriculum Hub") and Indonesian ("Beranda", "Data Sekolah"). The target audience consists of Indonesian principals, teachers, and operators who require standard localized terms.
- **Deep Nesting:** The user has to click "Workspace Enterprise", then find "Curriculum Hub", to actually edit Intracurricular or Cocurricular data. This buries the core application value.
- **Technical Subtitles:** Labels like "Next-generation workspace for KSP Gold. This environment is isolated from legacy RKJM, RKT, and RKAS systems." expose internal development phases rather than helping the user accomplish their tasks.

## 4. Hosting Risks
- Exposing WIP features and disabled buttons leads to a perceived lack of polish and breaks trust.
- The use of "Enterprise", "Hub", and "Registry" will confuse a Kepala Sekolah or Tim Kurikulum who expects terminology aligned with Kemendikdasmen (e.g., *Pengorganisasian Pembelajaran*).
- Having a "Legacy Workspace" mixed with an "Enterprise Workspace" implies system instability to the end user.

## 5. Recommended Menu Structure
Flatten the architecture to match the standard KSP formulation steps:
1. **Beranda** (Dashboard)
2. **Profil Sekolah** (Replaces Data Sekolah & School Profile)
3. **Karakteristik Peserta Didik** (Replaces Student Pedagogical Profile)
4. **Pengorganisasian Pembelajaran** (Replaces Curriculum Hub)
5. **Evaluasi Kurikulum** (Replaces Evaluation Hub)
6. **Administrasi Dokumen** (Replaces Administrative Metadata & Dokumen Perencanaan KSP tabs)
7. **Perpustakaan Dokumen** (Replaces Pusat Pengetahuan & Document Library)

*(Modules like Planning Intelligence, RKJM, RKT, and Pusat Audit should either be hidden if unready or properly localized and placed in advanced sections if strictly necessary)*.

## 6. Priority Matrix
- **P0 (Critical):** Translate and flatten the "Curriculum Hub" into "Pengorganisasian Pembelajaran" and make it a top-level menu. Remove all "WIP" badges and hide non-functional components.
- **P1 (High):** Standardize all English technical terms into standard Kemendikdasmen Indonesian.
- **P2 (Medium):** Consolidate the double-sidebar layout into a single, unified navigation tree.

## 7. FINAL DECISION
**NO GO**
The current UI is highly developer-centric, exposes internal project architecture ("Enterprise", "Legacy", "WIP"), and fails the user empathy test for Principals, Operators, and Curriculum Teams. 

**Next Steps:** Implement the recommended UX restructuring before proceeding to further domain modeling.
