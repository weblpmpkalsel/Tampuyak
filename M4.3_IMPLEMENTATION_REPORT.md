## 2. ASSEMBLER STRATEGY
- Updated the `assembleKspDocument` function in `KspDocumentAssembler.ts`.
- Mocked the immutable `Bab4KnowledgePayload` conforming strictly to the domains approved in M4.2 (ImplementationSupport, Monitoring, Evaluation, Reflection, FollowUp, ProfessionalDevelopment).

- Passed `bab4Payload` into `buildKspBab4Section`.

## 3. BUILDER STRATEGY
- Completely rewrote `buildKspBab4Section` in `KspBab4Structure.ts`.
- The Builder remains a pure consumer: it does not query services or run any calculations.
- Extracts information from `Bab4KnowledgePayload` and statically maps it to Canonical Blocks (`HeadingBlock`, `ParagraphBlock`, `ListBlock`, `TableBlock`).
- Performs strict validation to throw `IncompleteBab4KnowledgeError` if any mandatory domain is missing.

## 4. KNOWLEDGE MAPPING
The Knowledge Payload domains are explicitly mapped to their corresponding visual sections in BAB IV:
- **Pendampingan Implementasi Kurikulum:** Handled via `ImplementationSupportDomain` and mapped to a TableBlock.
- **Monitoring:** Handled via `MonitoringDomain` and mapped to a TableBlock.
- **Evaluasi:** Handled via `EvaluationDomain` and mapped to a ParagraphBlock (for narrative summary) and ListBlock (for mechanisms).
- **Refleksi:** Handled via `ReflectionDomain` and mapped to a ListBlock.
- **Tindak Lanjut:** Handled via `FollowUpDomain` and mapped to a ListBlock.
- **Pengembangan Profesional / Kurikulum:** Handled via `ProfessionalDevelopmentDomain` and mapped to a TableBlock.

## 5. CANONICAL MAPPING
- Only strictly defined Canonical Document Models were utilized (`HEADING`, `PARAGRAPH`, `LIST`, `TABLE`).
- Fixed types usage for table blocks by adhering to `TableRowNode` and `TableCellNode` structures.
- Zero styling logic, layout info, or CSS involved. Completely document-agnostic.
