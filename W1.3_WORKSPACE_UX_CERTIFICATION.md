# W1.3 WORKSPACE UX CERTIFICATION

## 1. NAVIGATION REVIEW
**Current State:** 
The `DataSekolahView` component acts as the primary data entry hub, utilizing a vertical left-sidebar with 14 distinct tabs (e.g., Dashboard, Administrasi Dokumen, Tahun Pelajaran, Profil & Identitas, Karakteristik & Lokasi, Sarana Prasarana, etc.). 

**Workflow:**
Operators currently update master data, pedagogical data (Vision, Mission), and administrative metadata all within this single monolithic view, before navigating to `KSP Studio` to assemble the document.

## 2. PAIN POINTS & DISCOVERABILITY ISSUES
1. **Monolithic Data Hub:** Mixing strictly administrative master data (NPSN, Sarpras, Budget) with deep pedagogical policies (Vision, Mission, Characteristics) inside `DataSekolahView` breaks mental models. A school operator updating the "Extracurricular Schedule" would struggle to find the right tab if it were just appended here.
2. **Scattered Domains:** 
   - `Peserta Didik` (student counts) and `Karakteristik` (student textual descriptions) are on separate tabs, hindering a unified "Student Profile" view.
   - `Profil & Identitas` houses Vision and Mission alongside raw school identity (NPSN).
3. **Scaling Limits:** Adding "Curriculum Organization" (Intrakurikuler, P5, Ekstrakurikuler) and "Evaluation Systems" directly to `DataSekolahView` would balloon the tab count to 18+, causing severe cognitive overload and navigation fatigue.

## 3. RECOMMENDED MENU HIERARCHY
To ensure scalability for the upcoming KSP domains, the workspace navigation should be semantically split into distinct functional domains. 

*Proposed Target Architecture:*

- **1. Data Pokok & Administrasi (Master Data)**
  - Profil Sekolah (Identity, Address)
  - Tahun Pelajaran
  - Pejabat Penandatangan
  - Administrasi Dokumen
  - Data Sarpras & Anggaran

- **2. Profil & Kebijakan Pendidikan (Pedagogical Hub)**
  - Visi, Misi, & Tujuan
  - Karakteristik Lingkungan
  - Profil Peserta Didik (Unified counts + characteristics)
  - Profil Pendidik & Tendik

- **3. Pengorganisasian Pembelajaran (Curriculum Hub)** *[Future]*
  - Intrakurikuler & Ekstrakurikuler
  - Projek P5
  - Bimbingan & Pendampingan
  - Kalender Akademik

- **4. Evaluasi & Tindak Lanjut (Evaluation Hub)** *[Future]*
  - Mekanisme Asesmen
  - Evaluasi Kurikulum
  - Rencana Tindak Lanjut

- **5. Studio Dokumen (Output Hub)**
  - KSP Studio
  - RKJM / RKT / RKAS Studio

## 4. FUTURE SCALABILITY
This domain-driven hierarchy ensures that new features (like P5 mapping or Assessment Guidelines) have a clear, intuitive home. It directly maps the user's mental workflow (Define School -> Define Pedagogy -> Define Curriculum -> Evaluate -> Print) to the UI.

## 5. FINAL DECISION
**NO GO FOR FLAT EXPANSION**

We MUST NOT add future KSP domains (Curriculum Organization, Evaluation) as new tabs inside the existing `DataSekolahView`. Before or during the implementation of W2.0 (Curriculum Organization), the workspace navigation SHOULD be refactored into these logical pedagogical hubs to prevent UI degradation. 

*(Note: As per this checkpoint's rules, no code implementation or refactoring was performed. This is purely an audit and certification.)*
