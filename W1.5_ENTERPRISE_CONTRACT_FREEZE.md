## 3. IMMUTABLE CONTRACTS (PART C)
- **IMMUTABLE**: `settings.school`, `settings.identitas`, `settings.academicYears`. Existing properties within these objects cannot be altered, renamed, or deleted.
- **EXTENDABLE**: `settings.karakteristik`, `settings.pesertaDidik`, `settings.gtk`, `settings.sarpras`, `settings.administrasi`. New properties may be added if required by the new Enterprise Workspace.
- **DEPRECATED**: None at this time.

## 4. ENTERPRISE EXTENSION RULES (PART D)
The future Enterprise Workspace MUST adhere to the following rules:
1. **Add new properties only:** Only additive changes are permitted to the global state tree.
2. **Never rename legacy properties:** `settings.school.name` must remain `settings.school.name`.
3. **Never delete legacy properties:** Legacy keys must be preserved.
4. **Never change existing types:** A `string` must remain a `string`; an `array` must remain an `array`.
5. **Never modify serializer formats:** JSON structure and `localStorage` parsing must remain backward-compatible. Heavy payloads must remain in their respective storage keys if applicable.

## 5. MIGRATION CONTRACT (PART E)
Coexistence strategy:
- **Legacy Workspace** continues to write directly to the legacy contract (`settings`).
- **Enterprise Workspace** writes to isolated state slices (e.g., `settings.curriculum`) or uses the `KspMetadataAdapter` (or similar future adapters) to read legacy data safely.
- No direct mutation of legacy nested structures from the Enterprise Workspace without using the established adapter patterns.

## 7. ARCHITECTURAL DECISION RECORD (PART G)
**ADR-005: Enterprise Contract Freeze**
- **Status:** ACCEPTED
- **Context:** The system needs to support a massive expansion for KSP Gold without destabilizing existing RKJM, RKT, and RKAS features.
- **Decision:** Freeze the existing Workspace state contracts. Enforce an append-only, extendable architecture where new features create new state slices (e.g., `settings.curriculum`) and use adapters to read legacy data.
- **Consequences:** Safe scaling, zero regressions for legacy features, but potential minor data duplication if not managed via adapters.

## 8. RISK ASSESSMENT
- **Risk:** New Enterprise developers might accidentally mutate legacy state properties directly.
- **Mitigation:** Strict code review guidelines and dependency enforcement via adapters. `KspMetadataAdapter` stands as the model for cross-domain data reading.

## FINAL DECISION
**GO**

The Enterprise Contract Freeze is fully established. The Legacy Workspace and its dependent documents are protected.
